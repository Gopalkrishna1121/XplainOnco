# XplainOnco

**Graph-Conditioned Soft Trees and Cross-Modal Attribution for Explainable Cancer Subtyping**
Bhagya Anand and Gopalkrishna Thumar, Vellore Institute of Technology. Artificial Intelligence course, Review 1.

XplainOnco classifies breast-cancer (PAM50) subtypes with one model, then explains a prediction as one connected
subnetwork on the STRING protein interaction map. A graph attention network and a differentiable tree ensemble
(NODE) are trained together under one loss. The graph embeddings of the genes a split reads move and sharpen that
split's threshold, and a cross-modal attribution layer then scores both views in the same unit.

- Paper: [`paper/XplainOnco_paper.docx`](paper/XplainOnco_paper.docx)
- Interactive site (source in [`docs/`](docs/)): open `docs/index.html`, or publish it with GitHub Pages
  (Settings, Pages, Deploy from a branch, `main`, folder `/docs`). It needs no network access.

Every number and picture on the website comes from a **synthetic cohort** (600 patients, 5 imbalanced classes,
planted driver modules, hubs and an AND-like gene pair) generated by `scripts/export_site_data.py`. It shows the
mechanics and lets the code be checked against a known answer. It is not evidence about real tumours.

## What is in the box

```
src/xplainonco/
  entmax.py            exact 1.5-entmax and its sigmoid form (entmoid15)
  graph_branch.py      GAT with one learnable gate per STRING edge (Eq. 1)
  tree_branch.py       NODE with node-conditioned thresholds and temperatures (Eqs. 2-5)
  fusion.py            bidirectional cross-attention (Eq. 6)
  model.py, losses.py, train.py       the model, the loss of Eq. 7, and the training loop
  attribution/         joint Integrated Gradients, edge IG, attention coupling, HSIC Lasso surrogate,
                       degree-corrected prizes, prize-collecting Steiner tree, enrichment (Eqs. 8-14)
  data/                synthetic cohort, fold-internal preprocessing, TCGA table loader
  evaluation/          nested CV, baselines and ablations, faithfulness, stability, weight randomisation
scripts/
  run_cv.py                nested CV with baselines, ablations and explanation tests
  export_site_data.py      trains on the synthetic cohort and writes docs/data/demo.js
  completeness_check.py    Integrated Gradients completeness check on the saved demo model
tests/                 24 tests, including closed-form entmoid checks, IG completeness, fold leakage
docs/                  the website
paper/                 the paper
```

## Install and run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
python -m pytest tests

python scripts/run_cv.py --quick          # synthetic cohort, a few minutes on a laptop CPU
python scripts/export_site_data.py        # regenerates docs/data/demo.js, about 10 minutes on 2 cores
python scripts/completeness_check.py      # IG completeness gap on the saved demo model
```

For TCGA-BRCA, put the tables in the layout described in [`docs/DATA.md`](docs/DATA.md) and run
`python scripts/run_cv.py --data path/to/folder` (add `--withhold-label-genes` for the PAM50-withheld experiment).
The full protocol is 5 outer folds x 3 repeats with 1,500 genes per fold and needs a GPU.

## Evaluation protocol (as implemented)

Nested stratified cross-validation (5 outer folds x 3 repeats, an inner split for early stopping), macro-F1 as the
primary metric, the corrected resampled t-test of Nadeau and Bengio for model comparisons, rank-biased overlap
(p = 0.9) and Jaccard overlap for stability across folds, deletion and insertion curves for faithfulness, the
cascading weight-randomisation check of Adebayo et al., and an offline hypergeometric enrichment test against a GMT
file you supply. Baselines: XGBoost with TreeSHAP (B1), the graph branch alone (B2), late fusion (B4). Ablations: no
conditioning (A1), concatenation instead of cross-attention (A2), both (A3). All gene selection, standardisation and
the Integrated Gradients baseline are fitted inside each training fold.

## Smoke-test numbers on synthetic data

These only show that the pipeline runs end to end. The synthetic task is easy for trees, so XGBoost scores near
perfect, and the single splits are noisy.

`python scripts/run_cv.py --quick` on the synthetic cohort: 3 outer folds, 1 repeat, 48 trees, 40 epochs, 4 patients
per subtype for attribution. Output in `results/cv_quick_synthetic.json`. Macro-F1 over the 3 outer test folds:

| Model | Macro-F1 (mean, std) |
|---|---|
| B1 XGBoost | 0.998, 0.002 |
| B4 late fusion | 0.996, 0.003 |
| A2 no cross-attention | 0.864, 0.048 |
| A3 neither | 0.831, 0.033 |
| XplainOnco | 0.815, 0.087 |
| A1 no conditioning | 0.622, 0.341 |
| B2 graph branch alone | 0.194, 0.022 |

How to read this: with three folds and these tiny settings, nothing separates XplainOnco from its ablations (the
corrected t-test p-values against A1, A2 and A3 are 0.73, 0.77 and 0.91). A1's mean is dragged down by one fold where
training stopped after 11 epochs at 0.14, which is a failed run and not an ablation effect. XplainOnco is below
XGBoost on this task, and its gene rankings were far less stable across folds (rank-biased overlap 0.10 to 0.24)
than TreeSHAP on XGBoost (0.60 to 0.78); the attribution here used only 4 patients per subtype. The paper's
hypotheses H1 to H3 are not supported by this run, and it is too small to count against them either. The full
protocol on real data is what would decide.

## Where this implementation differs from the paper

These are choices made while writing the code, not findings.

1. **Bounded conditioning.** The threshold shift and the log-temperature are passed through `tanh` (bounds 0.5), and
   the conditioning networks train at one tenth of the base learning rate. Without this the conditioned model overfit
   small synthetic cohorts. The paper's Eqs. 4 and 5 are unbounded.
2. **Gene selection** uses an ordinary ANOVA F-test with Benjamini-Hochberg correction, not the limma moderated
   t-test, because limma is an R package.
3. **Surrogate.** Block HSIC Lasso with a closed-form centred delta kernel on the neighbourhood masks and a positive
   `lars_path` solve. Enrichment is an offline hypergeometric test, not gseapy.
4. **Edge gates** follow Eq. 1 literally: the gate multiplies a message after the attention softmax.
5. **Integrated Gradients** uses 64 Gauss-Legendre steps by default. On the synthetic demo model the completeness
   gap was between 0% and 5% of the logit change at 64 steps and under 0.3% at 256
   (`scripts/completeness_check.py`).
6. **ComBat** batch correction is optional and, as written, corrects train and test samples together, so it is not
   strictly fitted on the training fold alone.
7. **Weight-randomisation check.** On the synthetic demo model the explanation scores stayed correlated with the
   originals (Spearman about 0.5 to 0.7) after every layer was randomised. That is a failed check as it stands. A
   likely cause is the input-difference factor in Integrated Gradients, which does not depend on the weights, but
   this has not been separated from a real fault.

## Reproducibility

Seeds are fixed in the scripts. The demo model is saved to `results/demo_model.pt` by `export_site_data.py`
(not committed). Exact timings depend on your CPU and thread count.
